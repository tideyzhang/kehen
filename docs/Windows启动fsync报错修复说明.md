# Windows 启动 fsync 报错：排查与修复

版本：0.3.4；排查日期：2026-09-14。

## 已确认的问题

教室截图显示“课堂积分无法启动：EPERM: operation not permitted, fsync”。从用户拷回的安装目录中读取 resources/app.asar，确认版本为0.3.3，数据保存代码与本地源码一致。

原保存流程：写临时数据库 → 以只读 r 打开临时文件 → fsync → 替换正式数据库。Windows 的 FlushFileBuffers 要求文件句柄具有 GENERIC_WRITE 权限，原只读句柄不满足要求。因此启动时的首次保存也会失败。这是程序的跨平台实现缺陷。

微软说明：https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-flushfilebuffers

此次未发现拷回安装目录中包含 classroom.db、日志或临时数据库。安装文件夹与用户数据文件夹不同，不能凭此次检查断言教室数据损坏或完整，也没有证据需要归因于坚果云或杀毒软件。

## 修复

将临时文件重新打开方式改为 r+，提供读写权限；保留 fsync、关闭句柄、原子替换和失败回滚。没有捕获并忽略 EPERM，也没有关闭数据落盘检查。

## 验证

- 在隔离测试中模拟 Windows 拒绝只读句柄 fsync：旧代码复现相同 EPERM；修复后启动、课次保存与重新打开通过。
- 模拟真正的 fsync I/O 错误：仍向上报错，正式数据库字节不变，内存事务回滚；恢复写盘后可以重试。
- 38项自动测试通过。Windows实际操作系统上的启动复测仍需教室电脑完成，Mac模拟不替代实机验证。

## 教室电脑更新与复测

1. 退出课堂积分，保留原用户数据。若有历史数据，先复制用户应用数据目录中的 classroom.db 和 backups；不要仅备份安装文件夹。该目录由 Electron 的 userData 路径决定，Windows 上在当前用户的应用数据目录内。
2. 使用“课堂积分 Setup 0.3.4.exe”更新安装，不先清理应用数据或卸载目录。
3. 启动，确认不再弹出 fsync 错误。
4. 检查原班级、名单与积分是否存在；若该电脑此前从未成功启动，空白初始界面属于正常情况。
5. 用测试班完成：开课 → 加1分 → 结束 → 退出 → 重开，确认该分数保存。
6. 若仍报错，请保留新错误截图，并记录发生在启动、导入还是记分阶段。不要删除数据库或把临时文件直接覆盖正式库。
